# 章节识别

预处理为每本书自动选一条切章规则，切出章节目录。自动选错时，可以按书指定规则。

## 规则

共 15 条，定义在 `scripts/lib/toc_rules.py`，排在前面的优先。

| # | 规则名 | 匹配的标题 |
| --- | --- | --- |
| 1 | `标准章节` | `第N章 标题`（也认 `回`、`节`、`集`、`话` 等单位），以及序章、楔子、尾声、后记、番外等 |
| 2 | `卷部册集` | `第N卷 标题`、`卷N 标题`、`上部` |
| 3 | `单位 序号` | `章一 标题`：单位字在前，序号在后 |
| 4 | `特殊章节` | 序章、楔子、番外这类标题，给没有编号章节的书用 |
| 5 | `数字 分隔符 标题` | `001、标题`、`1. 标题` |
| 6 | `大写数字 分隔符 标题` | `一、标题` |
| 7 | `大写数字 冒号 标题` | `三：标题` |
| 8 | `拉丁章节` | `Chapter 1`、`Part 2`、`Episode 3`、`No.4` |
| 9 | `括号装饰` | `【第一章 标题】`、`【001】标题` |
| 10 | `符号装饰` | `☆、标题`、`★ 标题` |
| 11 | `书名 序号` | `标题(12)`、`标题 12` |
| 12 | `分节阅读` | `第一页`、`分节阅读-3` |
| 13 | `纯序号行` | 整行只有一个序号：`一`、`1`、`【一】` |
| 14 | `顶格短行` | 顶格写的短行 |
| 15 | `通用激进` | 宽松的综合规则 |

13–15 号容易把正文当成标题，自动选择时不用，只能[按书指定](#按书指定规则)。

## 自动选择

候选规则切出来的结果要像一份目录，下面两种情况都会被否掉，换下一条规则：

- 命中少于 6 条，且平均每章超过 3 万字；
- 长度在 100 字到 10 万字之间的章节，加起来不到全书的 30%。

选定后在全书上再核对一次。仍不通过，就整本按约 5000 字一段切开，目录里标 `fallback: true`。

切完还会做几项修正：

- 明确的标题至少 8 条、且 90% 以上顶格写时，缩进又像句子（以 `。！？…；` 结尾或带逗号）的命中当作正文剔掉。
- 个别章节太长时，就地再切开。
- `第一卷` 这类卷标题单独成一个节点，标 `isVolume: true`。卷不计入章数，阅读器里显示为不能点的分组标题。

`符号装饰` 可能把 `※※※` 这样的分隔线当成标题。已经有别的规则选中时，它不会顶替；只有全书没有其他标题行时才用它。

## 按书指定规则

覆盖表是本机的 `scripts/toc-overrides.local.json`，已写进 `.gitignore`，不进版本库。在里面用书 id 指定规则名：

```json
{
  "青石巷-夜行": "标准章节",
  "// 青石巷-夜行": "写一句为什么要指定"
}
```

键以 `//` 开头的项是注释，加载时跳过。格式示例见 `scripts/toc-overrides.example.json`，预处理不读它。

改完后让这本书重新切章：

1. 删掉 `public/data/<id>_toc.json`。不删的话，预处理会因为源文件没变而跳过这本书。
2. 运行 `npm run preprocess`。日志里这本书会显示 `[覆盖]`。

源包已删的书也一样，会从 `.txt.gz` 重新切章。

- 没有本机覆盖表时，预处理照常运行，只是不做人工覆盖，全部按自动选择。开头会打印一行提示，写明它找的完整路径。
- 规则名写错时，预处理直接停下，并列出所有合法规则名。
- 键对不上任何书时，只打提示。

## 合集包的分册顺序

一个压缩包里有多个 `.txt` 时会并成一本书，顺序自动判断，见[合集包](library.md#合集包)。判断错了，或者日志里有 `[合集顺序]` 提示，就在覆盖表里给这本书写 `order`，按阅读顺序列出包里的文件名：

```json
{
  "青石巷合集-夜行": {
    "order": ["青石巷前传.txt", "青石巷.txt"],
    "rule": "标准章节"
  }
}
```

- `order` 里的名字写文件名就行，不用带包里的目录；包里不同目录下有同名文件时才要写完整路径。
- 没列出的文件不并入，可以用来去掉广告、重复的文件。
- `rule` 可选，作用和上面的规则名一样，对每一册都生效。
- 名字对不上包里的文件时，这本书处理失败，报错里列出包里实际有哪些文件。其他书照常处理。

改完后同样要删掉 `public/data/<id>_toc.json` 再运行 `npm run preprocess`。`order` 要读源包，所以源包必须在 `zip-novel/` 里。

## 修改切章规则

切章逻辑在 `scripts/lib/toc_rules.py`（规则表）和 `scripts/lib/toc.py`（选择与切分）。改了其中的切章逻辑，必须把 `scripts/lib/manifest.py` 里的 `PIPELINE_VERSION` 加 1。

- 加 1 后，下次预处理会重切全库（源包已删的书从 `.txt.gz` 重切），输出里有一行 `[流水线版本变更]`。
- 不加的话，所有书都会被跳过，网站上还是旧的切章结果。
- 只改注释、提示文案或文档时不要加，否则会白白重跑全库。

## 章节质量报表

`scripts/check_toc.py` 读取 `public/data/*_toc.json`，每本书一行：规则名、章数、卷数、章节字数分布、疑似误判、标题重复率、是否整本兜底。它只读数据，不重跑预处理。

```bash
python scripts/check_toc.py                    # 全库
python scripts/check_toc.py --book <id>        # 只看一本
python scripts/check_toc.py --data-dir <path>  # 换一个数据目录
```

退出码：0 读到了数据，1 没读到。

改规则前后各跑一次，对比两份结果：

```bash
python scripts/check_toc.py > before.txt
# 改规则，PIPELINE_VERSION 加 1，运行 npm run preprocess
python scripts/check_toc.py > after.txt
```
