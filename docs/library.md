# 书库与预处理

`npm run preprocess` 把 `zip-novel/` 里的压缩包变成网站用的书库文件。

## 生成的文件

| 文件 | 内容 |
| --- | --- |
| `public/books/<id>.txt.gz` | 正文，UTF-8，gzip 压缩 |
| `public/data/<id>_toc.json` | 章节目录 |
| `public/data/books.json` | 全库书单 |
| `.preprocess-manifest.json` | 预处理清单：每本书的指纹、id、字数、章数、压缩方式 |

`<id>` 由书名和作者拼成，特殊符号换成下划线。例如 `《青石巷》作者：夜行.zip` 的 id 是 `青石巷-夜行`。

## 处理流程

每本书依次：

1. 解压，取出包里全部 `.txt`。只有一个时它就是正文；有多个时按[合集包](#合集包)并成一本。
2. 识别编码，转成 UTF-8。
3. 切章节，见[章节识别](toc.md)。
4. 生成书名、作者的拼音首字母，供书架搜索（输入 `qstxx` 能搜到《青山踏雪行》）。
5. 压缩成 `.txt.gz`。
6. 检查生成的文件格式。
7. 记进清单。

全部处理完后写出 `books.json`，打印汇总，最后检查容量。

## 命名

- 书名和作者取自压缩包的文件名，推荐 `《书名》作者：某某.rar`。
- 书名和作者都相同的两本书，后来的那本 id 加 `_2`、`_3`，并打一条提示。
- id 分配后不再改变。
- 只改压缩包文件名、不改内容时，沿用原来的 id，不重新处理。

## 合集包

一个压缩包里有多个 `.txt` 时（分册合集、正文加外传），全部并成一本书，每个 `.txt` 是一册：

- 每册在目录里是一个卷标题，册名取自文件名（去掉书名号、`（校对版全本）`、`作者：…`）。
- 每册单独切章节。只切得出一段的小文件（资料、后记）不单列卷标题，整册算一章。
- 正文里每册前面加一行册名。

顺序依次按下面三条判断，前一条判断不了才看下一条：

1. 包名里用 `+` 列出了顺序，例如 `《甲+乙》`，就按这个顺序。
2. 文件名是同一个名字加序号（`书名1`、`书名2`、`书名（下）`、`第三部`），按序号排。文件名开头多出来的数字不算序号。
3. 最大的文件当正文放第一，其余按文件名排在后面。

日志里会打出 `[合集]` 和最终顺序。有体量不小的文件（达到最大文件的 20%）排在后面时，会多一条 `[合集顺序]` 提示：它可能该排在前面，请核对。顺序不对就在本机覆盖表里指定，见[合集包的分册顺序](toc.md#合集包的分册顺序)。

分册的位置记在清单里。源包删掉之后，从 `.txt.gz` 重新切章时仍然按册切。

以前的版本只取包里最大的 `.txt`，合集包会少几册，日志却显示成功。修复这些书的方法见[修复旧版处理过的合集包](#修复旧版处理过的合集包)。

## 什么时候跳过

三条都满足，这本书就跳过：

- 压缩包内容没变（按 SHA-256 比对）；
- 两个生成文件都在，且不是空文件；
- 切章逻辑的版本没变（`PIPELINE_VERSION`，见[修改切章规则](toc.md#修改切章规则)）。

想让某本书重新处理，删掉它的 `public/data/<id>_toc.json` 再跑一次。

## 处理完删除源包

```bash
npm run preprocess-clean
```

每本书处理成功后，删掉它在 `zip-novel/` 里的压缩包。以前处理过的书也会顺手删掉，所以对现有书库跑一次就能清空 `zip-novel/`。

这两种情况不删：

- 这本书处理失败；
- 生成的文件超过 25 MiB。

源包删了，书仍然留在网站上。

## 删除一本书

1. 删掉 `public/books/<id>.txt.gz` 和 `public/data/<id>_toc.json`。
2. 源包还在的话，从 `zip-novel/` 删掉。
3. 运行 `npm run preprocess`，这本书会从书单和清单里去掉。

只删了 `.txt.gz`、留着 `_toc.json` 时，这本书会暂时移出书单并打提示。把源包放回 `zip-novel/` 重跑就能恢复。

## 源包删掉以后

| 情况 | 预处理怎么做 |
| --- | --- |
| 两个文件都在 | 照常进书单 |
| 切章逻辑升级了，或 `_toc.json` 丢了 | 从 `.txt.gz` 重新切章 |
| `.txt.gz` 丢了 | 不进书单，清单保留记录；放回源包可重建 |
| 两个文件都没了 | 视为已删除，从清单里去掉 |

## 修复旧版处理过的合集包

旧版本处理过的合集包只有一册，而且源包和产物都没变，预处理会跳过它们。重做一本：

1. 把它的源包放回 `zip-novel/`。源包已删的话，`.txt.gz` 里只有当初留下的那一册，没法从它恢复。
2. 删掉 `public/data/<id>_toc.json`。
3. 运行 `npm run preprocess`，日志里这本书会显示 `[合集]`。

只要包里有多个 `.txt`，就会并成合集，不用另外设置。

## 备份清单

源包删掉之后，书单里这本书的信息全靠 `.preprocess-manifest.json`。用过 `preprocess-clean` 后，要把它和 `public/` 一起备份。

清单丢了的话，已删源包的书会从书单里消失（文件还在磁盘上），预处理最后会列出这些书。从备份恢复清单后重跑即可。

## 压缩方式

| 源包大小 | 压缩方式 |
| --- | --- |
| 不超过 10 MB | gzip 9 级 |
| 超过 10 MB | zopfli：再小约 8%，但慢得多，一本大书可能要两分钟 |

两种都输出标准 gzip。没装 zopfli 会报错退出。

## 容量上限

Cloudflare Pages 单个文件最大 25 MiB，最多 20000 个文件。每本书 2 个文件，约 9999 本到顶。

| 情况 | 结果 |
| --- | --- |
| 源压缩包超过 30 MB | 提示，处理会比较慢 |
| `.txt.gz` 在 20–25 MiB 之间 | 提示，照常通过 |
| 任一文件超过 25 MiB | 失败，指出是哪个文件 |
| 文件总数超过 20000 | 失败 |

统计的是 `public/books` 和 `public/data` 下的全部文件。删源包不会减少文件数，快到上限时要手动删书。

## 出错与退出码

一本书出错时，预处理记下原因，接着处理下一本。汇总里列出失败的书和原因，这些书本次不进书单。

以下问题会让预处理直接停下：缺 Python 依赖、缺解压 `.rar` 的工具、本机覆盖表里的规则名写错。

| 退出码 | 含义 |
| --- | --- |
| 0 | 一切正常 |
| 1 | 有书处理失败，或环境、配置有问题 |
| 2 | 超出容量上限，部署不上去 |

## books.json

每本书一条：id、书名、作者、拼音缩写、字数、章数、`.txt.gz` 大小。按源文件名排序，不带缩进。

## 直接调用 Python

```bash
python scripts/preprocess.py                  # 等同 npm run preprocess
python scripts/preprocess.py --delete-source  # 等同 npm run preprocess-clean
```
